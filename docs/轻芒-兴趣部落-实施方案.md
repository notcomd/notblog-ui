# 轻芒 · 兴趣部落 —— 前端实施方案

> 依据《docs/轻芒-兴趣部落-产品设计.md》，在 notblog-ui（Vue3 + Tailwind4 + daisyUI + VueCLI5）中落地。
> 后端：NotBlog .NET 微服务（F:\NotBlog），网关 YARP :9091（`/api` 前缀，PublicPaths 放行 `/api/identity/ready`、`/api/identity/auth`）。

## 一、现状与目标

- 现状：notblog-ui 为原型骨架（欢迎页/登录注册/占位 Dashboard/用户中心雏形），登录注册已验证码链路已对接 Identity。
- 目标：按设计文档重构为「兴趣部落」社区前端：毛玻璃 + 大圆角视觉体系、顶栏+侧边栏双栏框架、信息流/频道/会话/个人空间/详情页/弹幕六大模块，实时能力走 SignalR。

## 二、模块 × 后端 API 映射表

| 设计模块 | 后端端点（Message 服务，网关前缀 /api） | 状态 |
|---|---|---|
| 主页信息流 | `GET /tweets/timeline`（关注流）、`GET /tweets/trending`（热门） | ✅ |
| 卡片数据 | TweetDto：author/MediaUrls/content/LikeCount/FavoriteCount/ViewCount/IsLiked... | ✅ |
| 详情页 | `GET /tweets/{guid}`→TweetDetailResult、`POST /comments`、`GET /comments/tweet/{guid}`、`DELETE /comments/{guid}`、`POST|DELETE /tweets/{guid}/like|favorite`、`POST /tweets/{guid}/share|view` | ✅ |
| 关注 | `POST|DELETE /follows/{userGuid}`、`GET /follows/following|followers|feed` | ✅ |
| 频道 | `GET /circles/my`、`GET /circles/{guid}`（CircleDetailResult）、`GET /circles/{guid}/posts`、`POST /circles/join`、`DELETE /circles/{guid}/members/{userGuid}`（退出）、`GET /circles/{guid}/members` | ✅ |
| 会话 | `GET /sessions`、`GET /sessions/{id}/messages`、`POST /messages`、`GET /messages/unread`、`GET /sessions/unread-count`；好友 `GET /friends`、`GET /friends/search`、`POST /friends/request`；群组 `GET /groups`、`GET /groups/public` | ✅ |
| 实时（SignalR /MessageHub） | 客户端方法：SendMessage、SendFileMessage、MarkAsRead、RecallMessage、SendTypingIndicator、JoinSession、LeaveSession；服务端事件（IMessageClient）：ReceiveMessage、MessageRecalled、MessageRead、**UserOnline/UserOffline**、**TypingIndicator**、**UnreadCountUpdated**、UploadProgress | ✅ |
| 在线状态 | OnlineStatusDto + Hub 上下线事件（REST 查询端点待确认，可先用 Hub 事件维护本地状态） | ⚠️ |
| 个人空间·作品 | `GET /tweets/user/{userGuid}` | ✅ |
| 个人空间·收藏 | **后端无「我的收藏」查询端点**（有 favorite 写入无列表查询） | ❌ 需后端补 `GET /tweets/favorites/my`（或前端本地记录，不推荐） |
| 个人空间·文件 | `POST /files/upload|upload-image|chunk/*`（上传）；「我的文件列表」端点待确认 | ⚠️ |
| 账号与安全 | Identity：`POST /api/identity/ready/ChangeByPassword`、`GET|DELETE /api/identity/auth/oauth/linked|unlink`、`GET /api/identity/manger/user-manager/GetUserInfo` | ✅ |
| 视频 | Video 服务：VideoEndpoints（列表/详情）、VideoStreamEndpoints（播放流） | ✅ |
| **弹幕** | Video 服务已实现：`POST /api/videobarrage/`（发弹幕，JWT 归属、HTML 净化、≤100 字符）、`GET /api/videobarrage/{videoGuid}`（拉取） | ✅ 基础；⚠️ 实时推送无 SignalR 通道（前端可用定时轮询/进房拉取） |

### 后端缺口清单（需后端配合，本期前端先留适配层）
1. **我的收藏列表**：`GET /api/tweets/favorites/my`（分页）——个人空间「收藏」Tab 依赖。
2. 在线状态 REST 查询（若 Hub 事件 + 会话参与者状态不足）。
3. 个人文件库列表端点（若 FileDev 无查询接口）。
4. 弹幕实时广播（可选：Video 服务加 SignalR 或前端 3-5s 轮询兜底）。

## 三、前端技术方案

### 依赖新增
- `pinia`（全局状态：auth/theme/toast/unread/chat）
- `@microsoft/signalr`（Phase 4 会话实时）
- 其余沿用：vue-router 4、axios、tailwind 4、daisyUI

### 路由结构
```
/             → 重定向 /home
/home         主页信息流（3列网格 + 无限滚动）
/explore      探索/动态（trending + 关注 feed 切换）
/circles      频道（左列表 + 右频道流，1:2）
/chat         会话（好友/群聊 Tab + 聊天窗）
/chat/:sessionId
/users/:id    个人空间（作品/收藏/文件/账号安全）
/posts/:id    内容详情页（覆盖式路由，ESC/返回关闭）
/publish      发布（图文/视频/创建社区）—— Phase 6
/login、/verify-code（保留）
```
详情页用顶层路由 + 左侧内容区 `router-view` 过渡实现「覆盖但不丢信息流位置」（信息流组件 keep-alive + 滚动位置记忆）。

### 组件树
```
AppLayout
├─ TopBar（Logo | 全局搜索 | 铃铛(未读徽标) | 用户菜单 | 主题开关）
├─ SideNav（主页/发布+/频道/会话/探索 + 收缩控制；收缩时发布→FAB）
├─ main（router-view：HomeView/CirclesView/ChatView/ExploreView/UserSpaceView/PostDetailView）
├─ ToastHost（全局轻提示）
└─ GlobalSearchModal（Enter 触发全站模糊搜索）
PostCard（封面/作者/标题/❤️⭐️/更多菜单）· PostGrid（3列自适应）
CommentList / CommentItem（嵌套回复、排序、乐观更新）
DanmakuLayer + DanmakuPlayer（Phase 6）
```

### 状态（Pinia stores）
- `auth`：token/用户信息/登录态（登录链路已对接 Identity）
- `theme`：深/浅色切换（平滑过渡，持久化）
- `feed`：信息流数据/分页/加载态
- `chat`：会话列表/消息/未读/在线状态（SignalR 事件驱动）
- `toast`：全局提示队列
- `unread`：铃铛未读数（Hub UnreadCountUpdated）

### 样式系统
- 主色：暖橘（amber-500 系，与现有登录页一致）；点缀薄荷绿（emerald）
- 玻璃拟态工具类：`.glass`（backdrop-blur + bg-white/60 + border-white/40）、暗色 `.glass-dark`
- 大圆角：rounded-2xl/3xl；卡片 hover 上浮 + 阴影过渡；点击 scale(0.98)
- 主题切换：html[data-theme] + CSS transition（颜色渐变）

### 数据与容错
- `src/api/`：tweet.js / circle.js / comment.js / chat.js / friend.js / follow.js / video.js / danmaku.js / file.js / user.js
- dev 环境 `VUE_APP_USE_MOCK=true` 时 api 层走 mock（延续现有模式），联调切 false
- 统一分页：PagedResultOfT { list, page, size, total }（后端约定）

## 五、安全与兼容
- 所有写操作走 JWT（axios 拦截器已带 Bearer）；SignalR 连接 access_token query
- 弹幕文本前端限 30 字符 + 敏感词拦截（后端另有 100 字符 + HTML 净化兜底）
- 旧页面（Welcome/Dashboard/AppHelloWorld 等）保留路由但不进主导航，逐步下线

## 六、皮肤系统与背景图系统（一期实施，2026-08）

### 新增文件
- `src/assets/wallpapers.js`：12 张官方预设壁纸（清新/深邃/暖阳/极简 各 3），SVG data-URI 生成（离线、零网络请求），导出 `WALLPAPERS` / `wallpaperById()` / `wallpaperDataUri()`。
- `src/stores/skin.js`：皮肤 store，持久化键 `qingmang_skin`（`{ wallpaperId, blur, mask }`）。
- `src/components/common/BackgroundLayer.vue`：背景图层（图片层 + 渐变压暗层 + 蒙层），仅 AppLayout 挂载（管理端天然豁免）。
- `src/components/common/SkinPanel.vue`：皮肤面板（Teleport 到 body），双 Tab + 预览窗 + 壁纸横滚 + 滑块。
- `src/utils/skinStyle.js`：背景图层样式工具（BackgroundLayer 与预览窗共用，保证所见即所得）。
- `src/api/background.js`：`uploadBackground()` 真实对接 `POST /api/files/upload-image`（multipart，description=user-wallpaper → FileRef{fileId, fileUri}）。
- `src/utils/image.js`：压缩管线（`validateImageFile` 类型+5MB 校验、`compressImage` ≤1920px/WebP 0.8→0.6→0.4 降质量重试、`blobToDataUri` 本地兜底）。
- 管理端 `AdminFilesView.vue`：文件类型筛选新增【用户壁纸】分类（⚠️ 列表/删除端点仍缺口，空态提示）。

### 行为约定
- 模糊度 0~12px（默认 4）；蒙层 20%~80%（默认 40%，滑块最小值强制 20%）；`effectiveMask = clamp(mask + (深色 ? +12 : -8), 12, 85)`。
- 设置壁纸时 `Image()` 预加载，失败/3 秒超时 → 回退纯色 + toast"背景图加载失败，已切换纯色模式"。
- 持久化恢复时校验壁纸 id 仍存在（不存在 → 纯色）。
- **自定义上传（二期）**：v2 存储 `{ wallpaperId, customUrl, customFileId, useCustom, blur, mask }`（v1 自动迁移）；上传流程 = 校验（类型 JPG/PNG/WebP + ≤5MB）→ Canvas 压缩（≤1920px、WebP q0.8，超限降 q0.6/0.4）→ 上传后端 → 成功用 fileUri、失败本地 dataURI 兜底（toast 明示"仅本机可见"）→ 预加载校验 → 应用；「我的壁纸」缩略图点击 `selectCustom()` 切回；上传新图自动覆盖旧图（仅存最新一张）。
- TopBar 原「主题切换」按钮替换为「调色板」按钮 → 皮肤面板；深浅切换改在面板「颜色皮肤」Tab。

# 轻芒 · 兴趣部落 —— 管理端实施方案

> 依据《docs/轻芒-兴趣部落-管理端产品设计.md》在 notblog-ui 落地，复用用户端框架（玻璃拟态/大圆角/pinia/axios 双模）。

## 模块 × 后端能力映射

| 管理模块 | 后端端点 | 状态 |
|---|---|---|
| 工作台统计 | 在线人数/待审核数等无聚合端点；待审核数可调 `/api/audit/tweets/pending?pageSize=1` 取 TotalCount | ⚠️ 统计 mock + 审核数真实 |
| 用户列表 | `GET /api/identity/manger/user-manager/GetUserAllAsync`（⚠️ 无鉴权，返回完整 User：userGuid/userName/userEmail/imageCover/createDatetime/userAccessFail） | ✅ 列表真实；封禁/删除端点 ❌ 缺口 → mock |
| 内容审核 | `GET /api/audit/tweets/pending?page&pageSize`（返回 TotalCount）；`POST /api/audit/tweets/{guid}/approve`；`POST .../reject` body `{reason}` | ✅ 完整（仅待审核队列，无已通过/驳回列表端点） |
| 举报管理 | `GET /api/audit/reports/pending`（reportGuid/reporterGuid/targetType/targetGuid/reportReason/category/evidenceUrls/status/...）；`POST /api/audit/reports/{guid}/resolve` body `{action, note}`，**action=="removed" 删内容** | ✅ 待处理真实；已处理列表 ❌ → mock |
| 社区管理 | 全量社区列表 ❌（仅 /circles/my）；解散 `DELETE /api/circles/{guid}` ✓；转让 `POST /{guid}/transfer` ✓；成员 `GET/DELETE /{guid}/members` ✓ | ⚠️ 列表 mock、操作真实 |
| 文件管理 | 无管理列表/删除端点 | ❌ 全部 mock |
| 公报 | 无发送端点（MessagePush 类型存在但无管理 API） | ❌ 全部 mock |
| 在线人数/操作日志/权限分级 | 后端无 | ❌ mock |

### 缺口清单（后端待补）
1. 用户封禁/解封端点（可复用 UserAccessFail 锁定机制）
2. 用户删除端点（级联内容/评论/文件）
3. 公报发送/撤回端点（MessagePush 消息类型已存在）
4. 文件管理列表/删除端点（FileDev 层）
5. 社区全量列表端点（`GET /api/circles` 管理版）
6. 已处理举报列表 + 审核历史列表端点
7. 在线人数统计（Redis 连接管理已有数据，缺聚合端点）

## 前端技术方案

- 路由：`/admin` → AdminLayout（children：dashboard/users/content/reports/circles/files/announcements）；与用户端 AppLayout 平级
- **管理端默认深色**：进入 /admin 时强制 `data-theme=dark`（离开恢复用户偏好）
- 深蓝/藏青管理色调 + 暖橘/翠绿点缀；危险操作（删除/封禁/解散）统一 ConfirmDialog 二次确认 + 原因输入
- 组件：AdminLayout（顶栏+侧边栏，收缩支持）、AdminTable（通用表格：搜索/筛选/分页/多选）、ConfirmDialog、AdminModal、StatCard
- api/admin.js：audit/reports/users/circles/files/announcements 双模（mock 在 api/admin-mock.js）
- 用户端入口：顶栏用户菜单加「管理后台」链接；管理端顶栏提供「返回用户端」
